# 궁지 배회: 영상 격자 행동표 (실전 검증 중)

출처: [송기사TV — 이계의 울림 · 종전의 전조 3. 궁지 배회](https://www.youtube.com/watch?v=gXDwqbyJDck) (3:01). 맥 게임의 미션명, `모든 적 격퇴` 목표, 눈밭/선박 맵, 이리스·레인폴즈·비라쥬 배치를 영상과 확인했다. 오른쪽이 `+x`, 아래가 `+y`; 이동 좌표는 **해당 행동 직전 캐릭터 칸**을 `(0,0)`으로 잡는다. 카메라가 이동하면 픽셀 좌표는 새로 맞춘다. 기술 중심은 기술 선택 뒤 현재 격자에서 적 또는 빈칸의 상대 좌표로 적는다.

## 클릭 단위 확인표

| 순서 | 클릭 직전 확인 | 클릭 뒤 통과 조건 |
| --- | --- | --- |
| 1-1 이동 | 이리스 선택, `(0,0)` 시작 칸, `(+4,+1)` 파란 칸 | 경로선·이리스 이동 미리보기만 보이면 **아직 완료 아님**. `새벽의 징벌` 선택 뒤 범위에 초기 적 3명. |
| 1-2 첫 지점 | 주황 `평온한 밤의 선서`, 기갑 적 칸을 새 기준점으로 관측 | `(-1,-2)`를 선택하고 첫 확인을 누른 뒤에도 **두 번째 지점 선택 단계**인지 확인. |
| 1-2 둘째 지점 | 첫 지점의 선택 표시 확인 | 기갑 적 `(+1,0)` 칸을 새로 누르고 선택 표시가 옮겨진 것을 본 뒤 두 번째 확인. 확인 버튼만 연속 두 번 누르지 않음. |
| 1-4 투척 | 비라쥬 `(+3,0)` 이동, **하단** 파란 투척 기술 | 미리보기/효과 대상이 루크레치아. 사용 후 실제 루크레치아가 비라쥬 쪽으로 2칸 이동. |
| 1-5 재행동 | 비라쥬 현재 칸을 새 원점으로 잡음 | `(+2,0)` 이동을 마친 **새 칸**에서 왼쪽 `(-1,0)` 공격. 미리보기 상대 이름 `루크레치아`. |
| 2-1 광역기 | 레인폴즈 본인 이름과 현재 칸, `달의 암면` 아이콘 | 바로 오른쪽 `(+1,0)`이 **빈칸**이고 공략과 같은 적이 범위에 듦. 점유되면 좌표를 임의로 바꾸지 않음. |
| 2-2 열쇠 | 이리스의 실제 시작 칸과 이동 가능 범위 | 영상 1:21의 `(+2,-3)`은 미리보기. 실제 도착은 첫 열쇠 `(+1,-4)`이며, 이동 후 적 선택/전투 화면의 상대 이름 `서큐버스`. 열쇠 설명 창은 이동 성공이 아님. |

2-2 이후는 승리 화면까지 클릭 단위 전사가 완료되지 않았다. 이 상태로는 영상의 **전체 경로 재현을 검증했다고 말할 수 없다.** 남은 구간을 확정된 것으로 취급하지 않는다.

영상의 1턴 경로는 루크레치아를 1턴에 격퇴하지 않아 `전원 차단` 업적을 보증하지 않는다. `쾌속 승리`와 보물 상자도 아직 보증하지 않는다. 사용자의 우선순위는 **패배 시 재도전하면서 마지막 미션까지 승리**, 놓친 업적/상자는 기록 후 계속 진행이다. 크리스탈 사용 금지.

1:40의 `보물 발견`은 보물 획득 확정으로 해석하지 않는다. 영상 1:42에도 금색 표식이 남아 있으며 맥 게임에서는 해당 대화가 나타나지 않았다. 보물 획득 여부는 미검증이다. 영상 1:50에는 레인폴즈가 해골 궁병을 공격한다. 이후 정확한 행동 좌표는 아직 미전사다.

좌표 투영 시 현재 화면의 이리스·레인폴즈·비라쥬·식별 가능한 적을 기준점으로 새 격자를 맞춘다. [격자 참조 모듈](../../scripts/langrisser-grid-reference.mjs)은 계산만 수행한다. 10번째 출격에서는 시작 격자 4개 기준점의 오차가 0px였고, 이리스 `(+4,+1)` 이동 미리보기가 예상 칸과 일치했다. 카메라가 이동한 뒤에는 기존 픽셀 좌표를 쓰지 않았다. 이 방식은 좌표 착오를 줄이지만 적 배치·이동 가능 범위 차이까지 해결하지는 않는다.
