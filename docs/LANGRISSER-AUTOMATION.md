# 맥용 문 너머 저편 실행 도구

> 과거 Mac 전용 구현 기록이다. 현재 진행은 [다른 PC 사용 안내](LANGRISSER-OTHER-PC.md)와 [AGENTS.md](../AGENTS.md)의 CUA 수동 입력을 따른다. 아래 실행 앱·CLI 안내를 현재 PC 전투 실행 절차로 사용하지 않는다.

## 현재 상태

실행 방식은 [저장된 기록 기반 진행](LANGRISSER-RECORDED-PLAY.md)으로 변경했다. 118개 스테이지 문서와 로컬 실행·예외 분기·사용자 요청·관찰 재개 기능을 구현했다. 공략 재검색은 준비 단계에서만 한다.

- **이번 판 검증 실패로 게임 입력 중지.** 본편 1-4의 9턴, AUTO 꺼짐. 상자는 발견했으나 영상과 달리 마지막 적이 3283 HP로 생존했다. 1턴 추가 기술 입력 실수도 기록했다. [실제 검증 결과와 증거](LANGRISSER-VALIDATION-2026-09-27.md)를 참고한다.
- 완료 목표는 **전 스테이지 클리어 + 모든 업적 + 모든 상자/숨겨진 보물**이다. 클리어만 된 스테이지는 수집 완료로 집계하지 않는다.
- 일본 위키 목차에서 링크된 118개 스테이지를 읽고 핵심 공략, 출처, 수집 시각, 원문 해시를 저장했다.
- 외전 4장·본편 8장의 자료다. 한국 서버 전체 스테이지와의 대조는 미완료이며, 위키 일정표의 본편 9~11장은 목차에 개별 공략 링크가 없었다.
- 자료가 없는 턴별 해법을 생성한 것으로 표시하지 않는다. 화면 좌표가 없는 공략은 실행 가능한 스크립트가 아니다.
- 자동 완주 검증은 **0개**다. 메뉴 입력 검증은 실제로 통과했다. 본편 1-4 ‘섬의 손님’은 화면을 보며 조작을 보완해 8턴에 클리어했고 감옥 돌파 업적을 획득했다. 독립 프로그램만의 완주가 아니므로 자동 완주 수에는 포함하지 않는다. 전투 진입 계획 6단계는 한 번에 완주한 검증이 없으며, 분할된 마지막 2단계는 실제 앱에서 통과했다.
- 독립 Swift 화면 캡처 및 한국어 OCR은 실제 맥 게임 창에서 약 1초로 확인했다. 새 앱 실행 환경은 별도 macOS 권한이 필요하다.

## 실행 앱

`dist/Langrisser Pilot.app`을 실행한다. 이 앱은 현재 작업 폴더와 빌드 시 확인한 Node 설치 경로를 사용하므로, 다른 Mac으로 앱만 복사해서 사용하는 패키지는 아니다.

시스템 설정 → 개인정보 보호 및 보안에서 이 앱에 **기기 제어 및 데이터 접근**(macOS 27; 이전 버전의 손쉬운 사용)과 **화면 및 시스템 오디오 녹음**을 허용한다. 목록에 없다면 `+`로 앱을 선택한다. 파일 선택 창에서 `Command+Shift+G`를 누르고 아래 경로를 넣을 수 있다.

```
dist/Langrisser Pilot.app
```

권한 변경 후 앱을 다시 실행해 ‘권한 확인’을 누른다. ‘화면 읽기’는 게임 창과 OCR 결과를 `.runtime/langrisser`에 저장한다.

‘계획 실행’에서 `profiles/langrisser/main-1-4-details-recorded.json`을 선택하면 5초 후 시작한다. 게임을 전면에 두고 **‘섬의 손님’ 상세 화면**을 표시해야 한다. 스테이지 제목·승리 조건·보상 문구를 확인한 뒤 업적을 열고 닫는다. 성공은 메뉴 입력의 검증이며 전투 클리어를 의미하지 않는다. `main-1-4-enter-battle.json`은 출격에 스태미나 10을 사용하고 전투 시작까지 진행하는 미검증 초안이다. 전투를 끝까지 진행하는 계획은 아니다.

## 자료

- `docs/LANGRISSER-GUIDES.md`: 사람이 읽는 한국어 전략 요약과 각 원문 링크.
- `data/langrisser/guides.json`: 118개 공략의 구조화 자료와 누락 정보.
- `data/langrisser/progress.json`: 클리어 이력과 실제 화면에서 읽은 업적·상자 진행 수. 수집 누락이 있는 스테이지를 우선 재공략 대상으로 기록한다.
- `data/langrisser/completion-profiles.json`: 스테이지 제목, 클리어 보상 수령 표시, 업적·보물 수의 실제 화면 영역. 현재 본편 1-4와 1-5만 매핑했다.
- `data/langrisser/puzzle-routes.json`: 일부 퍼즐의 방향 순서. 실제 화면 검증 전이며 직접 실행하지 않는다.
- `data/langrisser/sources.json`: 수집 목록과 출처 메타데이터.
- `data/langrisser/video-sources.json`: 중국어 공략 모음에서 실제 확인한 155편의 영상 링크 목록. 영상 전체 내용 검토·한국 서버 전체 목록 대조는 별도다.
- `data/langrisser/video-routes.json`: 영상에서 확인한 행동과 시점, 미확인 사항. 이번 경로는 보조 검증에서 실패했으며 실행 불가다.
- `data/langrisser/execution-policy.json`: 문서화한 version 2 계획만 허용하며, 일시 불일치 재관찰·기록된 분기·막혔을 때 사용자 요청 정책을 저장한다.
- `.runtime/guide-research`: 공략 조사 작업 캐시. 프로그램 실행에 필요하지 않으며 버전 관리에서 제외한다.

## 명령행

```sh
npm run langrisser -- status
npm run langrisser -- objectives main-1-4
npm run langrisser -- audit main-1-4
npm run langrisser -- guides main-1-4
npm run langrisser -- doctor
npm run langrisser -- capture
npm run langrisser -- run profiles/langrisser/main-1-4-details-recorded.json
npm run langrisser -- run profiles/langrisser/main-1-4-details-recorded.json --live --delay --run-dir .runtime/langrisser/verify-001
npm run langrisser -- stop .runtime/langrisser/verify-001
```

`--live`가 없으면 계획 구문만 검증한다. 실전 입력은 `--live`와 실행 기록 경로를 모두 지정해야 한다. 앱과 명령행을 실행한 주체에 따라 macOS 권한 판정이 다를 수 있다.

실전 입력은 문서화한 version 2 계획만 허용한다. 기존 클릭 계획은 `RECORDED_PLAN_REQUIRED`로 거부된다. 전투 계획은 로컬 출처·순서·화면 매핑·계획 해시를 검토한 뒤 실행한다. 현재 9턴의 복구 기록은 준비 중이다. 메뉴 입력 예시는 `profiles/langrisser/main-1-4-details-recorded.json`이다.

`audit`는 지정한 스테이지 상세 화면을 두 번 캡처하고 제목·승리 조건·보상 영역을 확인한 뒤 업적과 보물 수를 대조한다. 배경에 비치는 다른 스테이지의 숫자는 제외한다. OCR이 누락되거나 두 화면의 수가 다르면 미확인으로 남긴다. 두 번 일치해도 OCR 오인식 가능성이 있으므로 이미지와 판정 기록을 함께 남긴다. 원문 수와 게임 내 총수가 다르면 완료 판정을 보류한다.

앱의 ‘계획 실행’에서 `main-1-4-audit.json`을 선택해 같은 기능을 실행할 수 있다. 전투 입력 없이 현재 상세 화면을 확인한다. 실제 앱에서도 업적 1/2·상자 0/1을 읽고 `objectives-incomplete`로 판정하는 것을 검증했다.

`objectiveMode: "all-objectives"`인 실행 계획에는 `auditAfter: true`가 필수다. 단계 실행이 끝나도 실제 수집 수가 부족하면 `stageComplete: false`로 남기고 다음 진행 대상으로 재공략을 제시한다. 아직 모든 스테이지를 순회하는 자동 전투 실행기는 없으며, 이 기능은 완료 판정과 누락 추적을 담당한다. 한국 서버 전체 목록 대조가 끝나기 전에는 확보한 118개가 모두 완료되어도 전체 캠페인 완료라고 표시하지 않는다.

원문에 ‘없음’이라고 명시된 항목만 0으로 저장한다. 업적·보물 정보가 없는 `side3-8`, `main-3-8`, `main-5-1`은 미상이다.

## 동작·중지·재개

입력마다 실행 전 OCR 조건 → 새 화면의 좌표 → 한 번 입력 → 실행 후 OCR 조건 확인 순서로 진행한다. 게임이 전면이 아니거나 창이 이동하거나 화면이 15초 이상 오래되면 입력을 거부한다. 입력 후 화면이 예상대로 바뀌지 않아도 같은 클릭을 반복하지 않는다.

실행 시작 시 게임 창을 한 번 활성화하고 이후에는 전면 여부를 검사한다. 실행 폴더의 `checkpoint.json`은 확정된 단계와 결과 불명 단계를 구분한다. `events.jsonl`과 단계별 PNG가 남는다. 결과가 불명확한 version 2 실행은 `needs-user`로 질문을 남긴다. 응답 후 저장된 계획의 결과 관찰부터 재개하며 입력을 자동 반복하지 않는다. `run.lock`이 남아 있으면 진행 중인 프로세스가 없는지 먼저 확인해야 한다. 기존 실행의 잠금이나 기록을 지워 임의 재시도하지 않는다.

앱의 ‘중지’, 명령행 `Ctrl+C`, 또는 `stop` 명령은 이후 입력을 중지한다. 이미 전송된 클릭은 되돌리지 않으며 진행 중인 입력 결과는 확인이 필요하다.

## 빌드·검증

```sh
python3 scripts/build-langrisser-app.py
npm test
```

macOS의 Swift 컴파일러가 필요하다. 앱은 이 Mac에서 만든 실행 파일에 임시 서명을 적용한다. 원격 서버로 게임 화면을 보내지 않으며 게임 메모리나 네트워크 프로토콜을 수정하지 않는다.

2026-09-27 검증: Swift 앱 빌드·실행, 실제 게임 OCR, 메뉴 왕복 자동 클릭 2단계 성공, 실제 앱에서 수집 완료 판정, 전체 29개 테스트 통과. 보조 조작으로 본편 1-4 클리어. 진행 기록은 `data/langrisser/progress.json`, 세부 전투 기록은 `data/langrisser/main-1-4-calibration.json`에 저장했다.

임시 서명된 앱을 재빌드하면 macOS 권한이 초기화될 수 있다. 현재 최종 빌드의 기기 제어·화면 녹음 재등록은 모두 확인됐다. 이후 전략 수정은 JSON/Node 코드로 진행하고, 네이티브 앱 재빌드는 별도로 필요한 경우에만 수행한다.

## 남은 구현

1. 본편 1-4 상자 발견은 이번 보조 검증에서 확인했다. 9턴 비치명타의 출처 기반 대응과 1턴 입력 실수를 보완하고, 처음부터 재검증 후 실제 업적 2/2·상자 1/1을 감사해야 한다.
2. 검증한 전투 경로를 카메라 이동을 인식하는 독립 실행 계획으로 변환하고 반복 재생 검증.
3. 각 스테이지의 실행 전후 조건·분기·보물·업적·승리 확인을 작성하고 검증.
4. 검증된 전투 계획만 다음 스테이지로 연결하며, 자료가 없는 장은 별도 공략 조사로 보완한다. 임의 플레이로 해법을 대체하지 않는다.

2026-09-27 이번 판 후속 검증: 관련 Node 테스트 25개 통과. 실제 전투는 9턴에서 중단했으며 자동 완주 검증 수는 0개로 유지했다.

기록 실행 기능 검증은 `test/langrisser-recorded-play.test.mjs`에 있다. 새 형식으로 문서화·컴파일한 메뉴 계획은 구문 검사를 마쳤으며, 이번 변경에서 실전 게임 입력은 보내지 않았다.
